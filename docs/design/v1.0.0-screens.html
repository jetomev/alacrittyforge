alacrittyForge, screen by screen

Every screen of the new alacrittyForge, drawn before any code is written: what you see, the order you move through it, what you pick instead of type, and how a save works. Your answers to the questions below decide what gets built.

Your brief: "rework alacrittyForge and bitlaForge to match the look of grubForge, so far the best of the 3." So this page follows grubForge 2.0 on purpose: the same frame, the same five-screen shape, the same Save with a review first. Every drawing is exactly 100 columns wide, the size of a small text console, so what you see here fits there.

Questions for you · my recommendation first

  1. Version number. 1.0.0: safe saving plus a full redesign makes this the first version I would call finished. The alternative is 0.3.0.
  2. Five screens, like grubForge: Overview, Settings, Themes, Shortcuts, Backups. Fonts become the "Text" group inside Settings instead of a screen of their own, and Backups becomes a screen (the code to restore one exists today, but nothing shows it).
  3. Which settings to show. Every setting Alacritty 0.17 has on Linux, in plain words, each showing "Not set (Alacritty uses …)" until you set it; rare ones in an Advanced group; macOS-only ones hidden. Today only settings already written in your file appear, and you can't add one.
  4. Keep your comments and layout when saving. Yes. Today a save rewrites the whole file and drops anything you wrote by hand. Keeping it needs python-tomlkit, which is in Arch's official repositories (and already on this computer).
  5. Colours. Themes gets "Adjust colours": change single colours by picking from swatches or typing a code, saved as your own copy of the theme. Or keep themes whole, as today.
  6. Shortcuts: press the keys to record them, with lists to pick from as a fallback. Yes. Today the key is typed by name.
  7. hypeForge's theme files (hypeforge-*.toml say "Do not edit; it is rewritten"). Shown and usable, never edited; "Adjust colours" on one saves a copy. The same rule as grubForge's entries from other tools.
  8. Old setting names (Alacritty renamed several, and warns every start). One "Update it" button on the Overview, listed in the review like any change.

What today's version gets wrong

I took stock of alacrittyForge 0.2.0 before drawing anything, and checked the serious findings on this computer. The redesign is a repair job as much as a new look.

Saving can lose or damage your settings
  • Clearing a font setting breaks the save. The "blank, inherit" choice writes an empty value the file format cannot hold; the save fails with "Failed to write config file".
  • A save rewrites the whole file, directly, dropping comments and your layout. If the file couldn't be read, a save would replace it with only the changed settings; the backup is the only thing that saves you.
  • Shortcut changes make one backup each. Only 20 are kept, so one big save can push out all your older backups. Edited shortcuts also lose any extra parts (mode, command).
  • Text in square brackets disappears from the theme preview, so lines like [colors.primary] don't show.
Still typed by hand

Shortcut keys and their text, every number, every colour code, theme names, and any setting not in alacrittyForge's own list.

Shown in program terms

Settings appear by their file names (window.decorations); one shortcut shows as raw data; a hidden control character in your Shift+Enter shortcut breaks the Shortcuts screen's picture.

Out of date

No --version or --help; the man page describes 0.1.1; the Shortcuts window lists keys that changed; the title bar says "AlacrittyForge", the old name.

Saving

F10 opens a review of every change, old → new, then saves: one backup, then a safe write that keeps your comments and layout (the new file is written next to the old one and swapped in only when it is complete). There is no Rebuild step: Alacritty notices the file and uses the changes in every open window. The few that need a new window (size, how it opens) say so in their row and in the review.

On a plain text console

Like grubForge, every screen must be readable on the text console (Ctrl+Alt+F3): 16 colours, a small font, no emoji. forgekit switches by itself; the work here is to take every fixed colour and symbol out of alacrittyForge's screens (today: about 70 colour codes and a dozen emoji) and use forgekit's roles instead. The same tests as grubForge check that nothing is cut off at 100 columns.

How it gets built

  1. Safe saving first, with tests: one backup per save, the safe write that keeps comments, refusing to save over a file it couldn't read, empty values handled, shortcuts saved whole. Proven against copies of real settings files before any screen changes.
  2. The frame, Overview and Settings on forgekit 0.5.0's pieces, including every setting from the table above.
  3. Themes and colours.
  4. Shortcuts, with key recording.
  5. Backups, the manual, --version/--help, the closing note, the text console, 100 columns; the name everywhere becomes alacrittyForge.
  6. Testing: a written test matrix; automated tests per screen; your own run in the KognogOS VM as a real package upgrade from 0.2.0; then the release (GitHub and the AUR), issues opened and closed for every finding.

If a piece turns out useful to bitlaForge and nogForge too (key recording, colour swatches), it moves into forgekit, as grubForge's did.
